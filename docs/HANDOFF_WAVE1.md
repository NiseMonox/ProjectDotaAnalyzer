**Java – tools/clarity-analyzer/.../ReplayAnalyzer.java** (output is schema_version 2 and stays backward compatible; it only fixes values and adds fields)
- **Coordinates (J1):** every position (heroes, wards, smokes incl. path, teamfight positions/casts, laning snapshots, buildings) is world = cell*128 + vec - 16384, falling back to the cell centre.
- **Wards (J2, J3):** tracked per ward entity, so re-warding the same spot is no longer dropped. destroyed_time comes from entity deletion (null if the ward was still alive at game end). Owner comes from m_hOwnerEntity → hero → player, with the purchase heuristic only as fallback. An unknown owner now gives player_slot -1 plus a team, instead of crediting player 0 or 5.
- **Illusions and clones (J4):** ignored via m_hReplicatingOtherHeroModel, plus a single primary hero entity per player.
- **Net worth (J5):** real value from m_vecDataTeam.N.m_iNetWorth, falling back to earned gold.
- **Final items (J6):** read from the hero's actual inventory (slots 0–5, backpack 6–8, neutral slot 16). Item names come from the EntityNames string table; the old last-6-purchases rule is the fallback.
- **Skill build (J7):** ability-entity m_iLevel increases, so passives and talents are included. Sub-abilities, Invoker's invoked spells and generic abilities are filtered. Accepted upgrades are capped by spent m_iAbilityPoints, or by hero level if that property is missing. Fallbacks: cast levels, then level-up correlation.
- **Objectives (J8):** team comes from the destroyed building's own name (goodguys/badguys), with denies flagged.
- **Score and first blood (J9):** counted from real hero deaths, excluding illusions, reincarnation/aegis deaths and denies.
- **Smokes (J10):**
  - A kill only counts if it is within 2500 units of the smoked group's path.
  - Results are now computed at the end of parsing. Before, they were computed when the smoke broke, so kills in the following 30 s were never seen.
  - New result code "caught" (only own deaths) and an objective_taken field.
- **Draft (J11):** taken from CDemoFileInfo picks_bans (which has the team).
- **Placeholders filled (J12):** player names and steam IDs, start_time = end_time − duration, match id, mode and winner as fallbacks. A buildings list is emitted. Region is not available in the replay and stays 0.
- **Player IDs (J13):** the hero m_iPlayerID scheme (0–9 or doubled) is detected from the (id, team) pair. Assist, chat and rune IDs are resolved separately by a team-consistency vote.
- **Hero names (J14):** the npc internal name is output.
- **Errors (J15):** each handler counts its errors and prints the first 3 to stderr. A truncated replay still produces JSON with "partial": true. Exit codes: 64 usage, 65 invalid replay, 66 unreadable file, 70 internal error; stdout is written as UTF-8.
- **Performance (J16):** FieldPath lookups are cached per class and missing properties are cached, so no per-tick exceptions.

- **[major]** `tools/clarity-analyzer/src/main/java/com/dotaanalyzer/ReplayAnalyzer.java:2533` — Both tier-4 towers marked destroyed when only one dies (shared unit name overrides per-entity death) _(lens: correctness)_
  - Both tier-4 towers of a team have the same unit name, npc_dota_goodguys_tower4 (or badguys). That name comes from both the combat log and EntityNames, which this code already treats as unit names for heroes and items. canonicalBuildingName keeps it unchanged, so both T4 BuildingRecords get the same b.name. handleDeath stores the first T4 death under that name (buildingDeathRaw.putIfAbsent, line 753). At output, buildingDeathRaw.get(b.name) takes precedence over the correct per-entity b.destroyedRaw (set from m_lifeState or deletion). As a result, every T4 of that team gets the first T4's death time. When a team loses exactly one T4 (a winner pushed into its base, or a GG with one T4 down), the surviving T4 is reported destroyed. When both die, the second one gets the wrong time. On the Python side, _normalize_buildings gives the two records sides by position, and building_status_bitmasks then clears both bits 9 and 10. The objective reconciliation cannot undo this. The wrong values reach MatchData.buildings (used by vision._build_towers for tower vision) and tower_status_radiant/dire.
  - Fix: Prefer the per-entity b.destroyedRaw whenever it is set, and use buildingDeathRaw only as a fallback for names that are unique among buildingsByEntityIndex. For names shared by several records (tier 4), assign each combat-log death time at most once: store a list of times per name instead of putIfAbsent, and give each time to the still-unassigned record whose destroyedRaw is closest. Leave a record alive when it has no entity evidence and no unassigned combat-log time.

- **[minor]** `backend/app/parser.py:605` — check_clarity_available can block the event loop while another caller's java -version probe is running _(lens: correctness)_
  - _java_ok holds the threading _java_probe_lock for the whole java -version subprocess (up to 30 s timeout) in a worker thread. check_clarity_available then does a blocking `with _java_probe_lock:` directly on the event-loop thread to read the cache. If a second request (for example /capabilities plus an upload right after startup, or two concurrent uploads) calls it while the first probe is running, the whole event loop freezes until the probe finishes. Contract C2 requires that the probe run in a thread so the event loop is not blocked.
  - Fix: Read the cache without the lock (`_java_probe.get(java)` is atomic under the GIL), or try `_java_probe_lock.acquire(blocking=False)` and fall through to the thread when it fails. Simplest: `return await asyncio.to_thread(_java_ok, java)` whenever the cache has no entry, and never take the lock on the loop thread.

What changed:
- **Admin and limits:** admin endpoints and /api/parse-local now need an X-Admin-Token header that matches ADMIN_TOKEN, and return 403 when it is unset. Per-IP sliding-window rate limits apply to upload, fetch, request-parse and new AI-coach generations; cache hits are free and IPv6 clients are grouped by /64. A per-UTC-day cap (AI_COACH_DAILY_LIMIT, default 200) limits new LLM-backed reports; the counter is saved to disk so a restart does not reset it.
- **Uploads:**
  - A middleware returns 413 early (from Content-Length or a byte count), and the endpoint checks the rate limit and parser availability before reading the body.
  - Files are copied and hashed in a worker thread, checked for the PBDEMS2 header, and stored as `<sha256[:32]>.dem`, so a repeat upload is a cache hit and client filenames are never used.
